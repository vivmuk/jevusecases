Case 01easy

Spreadsheet Data Categorisation

00:53 in the video

Give every row one label from a fixed list, and nothing outside the list.

state
one row of raw text, on its own
question
choice, over the labels you allow
answer
one label plus its probability

A sheet script posts each row to Jev together with the allowed categories, and writes the winning label into the target column. Because the categories are declared in the request, a label outside them cannot come back, which is what keeps a hand-checked column from growing invented values. Rows under your confidence threshold are left blank for a human.

Example prompts

Prompt 1 of 2

state + question 
state: CARD PAYMENT 04/10 SQ *BLUE BOTTLE 4.80

question: category=choice:Which budget category does this bank line belong to?|groceries:Food and groceries,transport:Travel and transport,subs:Subscriptions,ignore:Not a real expense

Prompt 2 of 2

state + question 
state: DIRECT DEBIT NORTHWIND POWER 61.20 OCT

question: category=choice:Which budget category?|utilities:Power, water, internet,rent:Housing,subs:Subscriptions,ignore:Not a real expense

In plain words

No jargon. Four things, in order: what comes in, what you hand it, what it does, and what you get back.Green is what you supply. Orange is what the model decides and returns.

  1. 01 What comes in

    One row from a bank export, exactly as it appears.

  2. 02 What you hand it

    The list of categories you allow, written out in advance.

  3. 03 What it does

    Label every row the same way, so ten thousand rows read like one.

  4. 04 What you get back

    One category per row, plus how sure it is from 0 to 1.

The Jev step: the choice comes from a fixed set of answers you wrote down, not from a model writing prose.

Case 02easy

Customer Inquiry Triage and Routing

01:31 in the video

Read intent from an incoming message and send it down the right path.

state
the message body
question
choice for intent, a noul for each gate, a score for urgency
answer

An automation tool hands the inquiry text to Jev and gets back both a category and a confidence. The routing rule lives in your code: high confidence goes to the automated path, low confidence goes to a person. The probability is the useful half of the answer, because it is the model telling you it does not know.

Case 08easy

Output Verification and Model Calibration

05:04 in the video

Measure how often the decision is right before you trust it with anything.

state
one record from a labelled set, with the answer withheld
question
the same question you will ask in production
answer
the model’s pick, for you to compare against the human answer

Build a validation set of a few dozen to a few hundred records a human has already labelled, run the loop without showing the answers, and count the matches. Misclassifications tell you where the labels are ambiguous, and the spread of probabilities tells you where the confidence cutoff belongs. The video’s own advice is fifty records or more before production; tune the cutoff on one set and hold some records back.

Case 09intermediate

Agent Skill Selection

06:21 in the video

Let the agent pick the right skill before it loads any of them.

state
the user’s prompt
question
choice, one option per skill in the library
answer
the skill to load, plus how sure it is

You do not have to put every skill description in the context window to choose one. Register the skills as the options, send the prompt, and load only the winner. In the video’s own counting, 145 skills were matched in about five seconds across fourteen tests against roughly thirty for the larger model, and a separate test over 182 skills cut wrong picks by more than half. Keep the option list to the skills that are real candidates for this agent.

07:37 in the video

answer

Each message is bucketed as an actionable inquiry, a sponsorship, spam or phishing; spam and phishing are dropped, and only the messages that need a reply reach the model that drafts. Case 16advanced

Zero LLM Retrieval Engine

10:30 in the video

state
the visitor’s question
question

answer

Turn the transcripts you already have into topic units with a short description each, then match the question against them. The visitor gets the actual answer slot, a lesson number or a video timestamp, which is more useful than a paragraph about it and costs nothing to generate. The corpus has to be genuinely finite for this to work, and the no-match case must be allowed to come back empty.

Prompt 2 of 2

state + question 
state: Visitor asked: can it write my newsletter for me?

One Message, Three Typed Questions, One Call.

The State

Order A-104 was charged twice this morning. I need the duplicate charge refunded.

The Questions

yes or no, returned as a probability
choice
one of four teams, a probability each

where it lands on four urgency levels

0.99yes

1.48concerned 0.50, urgent 0.49

That 1.48 is the part to notice. It is not a rounding error, it is the model saying it sits between two levels, and the rule that decides what to do about that lives in your code. 411 input tokens, 0.0000173 dollars, about four tenths of a second.

Putting one in production

Four Steps, and the Failure That Costs You the Most.

  1. Get One Key

    One of TYPESAFE_API_KEY, OPENROUTER_API_KEY, or a Venice key set as VENICE_API_KEY. The transports are interchangeable, so keep the fallback in your config rather than in your head.

  2. Send a State and Typed Questions

    One POST with the text to judge and a map of questions. Name every item you are asking about inside the question itself, and send only the fields the question needs.

  3. Write the Thresholds in Your Code

    High confidence acts, medium confirms, low goes to a person. Keep one cutoff per risk rather than one number for the whole system, and never carry a yes-or-no cutoff over to a choice.

  4. Prove It on 50 Records First

    Labelled records, answers withheld, count the matches, then sweep the cutoff and see what each one costs you in coverage. This is the step that separates a decision model you trust from one you hope works.

  • Choice boundariesIf the answers can be written down before the question is asked, it is a decision. If they cannot, it is a writing job and it belongs with a language model.
  • Confidence safeguardsEvery decision gets a floor below which a person decides instead, and the floor is written next to the risk it gates.
  • Validation setsFifty labelled records or more before it touches real traffic, and the labels themselves checked for ambiguity when two of them disagree.

Where it loses. Counting and arithmetic belong in code. Multi-step reasoning, anything needing prose back, and adversarial text all want the bigger model. A confident wrong tick is still wrong, so the threshold in your code is the part that keeps you honest.
